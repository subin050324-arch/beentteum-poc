# 과제2. 실시간 혼잡도 개표 비즈니스 로직

빈틈 서비스의 핵심 비즈니스 로직인 실시간 혼잡도 개표 함수 및 검증 테스트 명세입니다.

---

## 1. 개표 규칙 숫자 명세

1. **시간 윈도우 (`T`)**: **`60분`**
   - 현재 조회 시각 기준 60분 이내에 접수된 제보만 유효 제보로 집계합니다. (60분 초과 제보는 자동 제외)
2. **중복 제보 처리**: **`최신 1건만 인정`**
   - 동일 회원이 60분 이내 여러 번 제보한 경우, 가장 마지막에 등록된 1건만 유효값으로 유지합니다.
3. **최소 유효 건수 (`N`)**: **`3건`**
   - 중복 제거 후 남은 최종 유효 제보가 3건 미만인 경우, 임의의 상태를 추정 생성하지 않고 즉시 **`정보부족`**을 반환합니다.
4. **다수결 및 동점 규칙**:
   - `여유`, `보통`, `혼잡` 중 최빈값을 현재 혼잡도로 결정합니다.
   - 최빈값이 동수(동점)일 경우, **동점 후보 상태 중 가장 최근에 제출된 제보의 상태**를 최종 상태로 채택합니다.

---

## 2. 테스트 항목 및 실행 방법

### 단위 테스트 4종
- `test_zeroReports`: 제보 0건일 때 `정보부족` 반환 검증
- `test_duplicateUserReports`: 동일 사용자 중복 제보 시 최신 1건만 반영 검증
- `test_tieBreakRules`: 동점 발생 시 최신 등록 상태 채택 검증
- `test_windowBoundary`: 61분 전 제보 제외로 최소 건수 미달 시 `정보부족` 반환 검증

### 테스트 실행 명령어
```bash
./gradlew test
```

## 3. 코딩테스트 풀이 및 빈틈 서비스 연결

- **선택 문제**: 프로그래머스 Lv.1 — 신고 결과 받기
- **빈틈과의 공통점 (3줄 요약)**:
  1. **중복 데이터 필터링**: 동일 대상에 대한 중복 신고를 1회로 거르는 코테 로직처럼, 빈틈 역시 어뷰징 방지를 위해 동일 사용자의 반복 제보 중 최신 1건만 유효값으로 처리함.
  2. **임계치 기준 상태 처리**: 누적 신고 수가 k건 이상일 때만 제재 대상이 되듯, 빈틈도 유효 제보가 최소 3건 이상 쌓여야만 혼잡도를 확정하고 미달 시 '정보부족'으로 예외 처리함.
  3. **Map·Set을 활용한 카운팅 구조**: 데이터를 순회하며 고유 키값(유저/상태)으로 그룹핑하고 빈도수를 집계하는 자료구조 및 처리 흐름이 동일함.
